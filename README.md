# ОТБ — демонстрационная версия

Статическая демонстрация управления НИР, публикациями, РИД, поручениями и заданиями. Работает на GitHub Pages без сервера приложения и базы данных.

- Исходные работы, сотрудники и суммы вымышлены.
- Вход и разграничение прав не реализованы. Страница доступна всем, у кого есть ссылка.
- Изменения сохраняются в localStorage только этого браузера и не передаются серверу. У других посетителей своя копия. Очистка данных браузера удаляет изменения.
- Можно просматривать работы и задания, создавать учебные работы, менять прогноз выручки и затрат, видеть историю собственных изменений и сбрасывать примеры.
- Платежи, подтверждённая выручка и затраты учитываются раздельно. Прогноз на весь срок = подтверждённый факт + оставшаяся оценка. Прибыль = выручка − затраты. Основной показатель — прибыль / затраты × 100%; дополнительный — прибыль / выручка × 100%. Неизвестное значение отличается от нуля.
- Суммы экономики задаются без возмещаемого НДС; невозмещаемый НДС включается в затраты. Автоматического расчёта НДС, ставок труда, оборудования и общих расходов нет.
- Это демонстрация интерфейса и вычислений. Общая база, настоящий вход, полномочия, согласования, серверный аудит и резервное копирование остаются в отдельном приложении Django и в эту версию не включены.

## Запуск

Откройте опубликованную страницу. Для разработки достаточно любого статического HTTP-сервера в этой папке. Все пути относительные, маршруты используют `#`, поэтому сайт работает и в подпапке GitHub Pages.

Проверка вычислений: `node --test tests/model.test.cjs`.

## Публикация

Публикуются только `index.html`, `app.css`, `app.js`, `data.js`, `model.js`, `.nojekyll` и этот README. Каталоги с проверками и рабочие файлы Django не публикуются.

GitHub Pages: ветка `main`, папка `/` (Deploy from a branch). `.nojekyll` отключает обработку статических файлов Jekyll. Источник: [документация GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

Для обновления внесите изменения в исходники `otb-pages`, выполните проверки и опубликуйте новую версию. Изменения в локальной базе Django автоматически сюда не переносятся.
